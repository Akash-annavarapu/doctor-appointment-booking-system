# Week 7 — Gemini-generated cases executed using Playwright (isolated)

## Why this change exists

Kavi Sir's 31 October review requested the **last stage**: TestPilot generates positive, negative and edge cases from user stories; **Playwright must execute the corresponding scenarios** against the doctor appointment application, not merely show an unrelated green CI suite.

The earlier 188-test pass relates to the **prewritten regression suite**. It is not evidence of executing Gemini cases. This implementation adds Playwright API tests for a **real Gemini US-017 export**, and a separate source-derived edge case US-018. Do not present them as passing until the new CI run succeeds.

## Source and traceability

The source is the genuine TestPilot Lab export dated **2026-10-26 18:35 UTC**, generated by Google Gemini for **US-017: Book an available appointment**. The Lab's original output was 4 cases, all marked NOT_RUN. A protected signed receipt expired after 30 minutes and is deliberately **not** committed.

| Source | Gemini case title / origin | Classification | Reviewed executable assertion |
| --- | --- | --- | --- |
| AI-001 / US-017 | Successfully book an open appointment slot as a patient | Positive | POST creates a Pending appointment; verify MongoDB has exactly one |
| AI-002 / US-017 | Reject booking request for an unavailable appointment time slot | Negative | First patient books, second receives HTTP 409; verify one active booking |
| AI-003 / US-017 | Reject booking request with missing mandatory fields | Negative | Omit required booking parameters; HTTP 400 and zero inserted appointments |
| AI-004 / US-017 | Deny appointment booking for unauthenticated users | Security / Negative | POST without JWT returns HTTP 401 and zero inserted appointments |
| US-018 (source-derived, **not Gemini**) | Two patients attempt to book the same appointment time concurrently | Edge | Concurrent API calls return exactly 201 and 409; one active MongoDB row |

Original LLM-provided `doctorId: DOC-123`, fixed 2026-11-01 timestamps, and unspecified `slotTime` parameter are **not valid executable fixtures** for the healthcare backend. The reviewed tests translate the scenario **intent** into actual API fields `doctorId`, `appointmentDate` and `appointmentTime` and use a dynamically selected future Monday with a doctor configured for 09:00–11:00. This adaptation must be included in the final human review record.

The cases are implemented in `e2e/tests/generated-booking.api.spec.cjs`. Each ID appears in the Playwright title, allowing a reviewer to trace the output to the correct Gemini candidate.

## Execution boundary

- GitHub Actions runs a **MongoDB 7 service container**; the healthcare API runs only on `http://127.0.0.1:5199`.
- The database is hard-coded as `mongodb://127.0.0.1:27017/testpilot_generated_test`; the test verifies `NODE_ENV=test`, `MONGO_URI`, `MONGO_URI_TEST`, and `TESTPILOT_ISOLATED_API=1` before it can seed data.
- Patients and doctors are fabricated, use `example.invalid` emails, and are cleared between tests. No production appointments or patient data are accessed.
- Playwright runs **reviewed static JavaScript**, never Gemini-generated code. This is execution of **reviewed Gemini scenario intents**, not literal execution of arbitrary model-generated steps.
- Existing read-only production checks and independent 36-case manual catalog remain unchanged.

## Local reproduction (requires Node 22, Chromium, MongoDB on localhost)

```bash
npm ci --prefix client
npm ci --prefix server
npm install --prefix e2e --no-audit --no-fund
cd e2e && npx playwright install chromium && cd ..
VITE_API_BASE_URL=http://127.0.0.1:4173/api/v1 npm run build --prefix client
NODE_ENV=test TESTPILOT_ISOLATED_API=1 \
  MONGO_URI=mongodb://127.0.0.1:27017/testpilot_generated_test \
  MONGO_URI_TEST=mongodb://127.0.0.1:27017/testpilot_generated_test \
  JWT_SECRET=local-generated-case-only-secret \
  npm test --prefix e2e
```

The Playwright config starts the disposable local healthcare API only in the isolated mode. Without the mode flag, the new tests are skipped. Never point this runner at a remote MongoDB or production backend.
