### Evidence still required from actual people and the actual model

1. **10 genuine Gemini runs across US-001, US-005 and US-017**, containing full outputs and version/variant notes, plus a real human quality rating for each run (1–5 for completeness, accuracy and healthcare relevance). Never invent LLM outputs or backfill ratings.
2. **Independent reviewer A and B records**, scored separately for each sampled story against the **same immutable** AI and manual case sets. Record case IDs/steps and resolve any disagreements with the reviewers.
3. **At least two actual peer usability sessions**, with explicit consent, start/end timing, outcomes for all six tasks, observed difficulties, device/browser and feedback.
4. **Team and mentor/faculty validation** of the completed comparison, limitations and the final report. Sign-off cannot be generated by code.

## How to run ten genuine prompts (source-controlled, resumable)

In a private environment with Node.js 22+ and a working unbilled Gemini API key:

```bash
# From repository root; never commit or paste the API key
export AI_PROVIDER=gemini
export GEMINI_API_KEY='<PRIVATE VALUE SET LOCALLY>'
node testpilot-lab/tenRunStudy.cjs ./testpilot-real-llm-study.json
```

The script calls the **existing, validated** `generateCases` implementation using the four approved prompt variants and source-grounded acceptance criteria. Every genuine provider response is saved immediately to the same local JSON file. A quota error stops the script without inventing output; run the same command later to resume from the last genuine response. Ten calls depend on real provider access and quota, so **adding this script is not evidence the experiments ran**.

The generated `humanRatings` fields remain `null`. A human must grade each stored output and add observations and review timestamps. Alternative: conduct and export the ten iterations directly through the Lab's prompt-engineering panel. The two formats have similar study fields; preserve model and reviewer provenance.

## Collect authentic independent reviews and usability exports

Open https://testpilot-lab.onrender.com/ and generate the source-grounded case set. Have two different reviewers independently evaluate the exact same candidate set and save each review; export the peer-review result *per story*, and document/discuss conflicts. The forms use self-declared identities; for faculty, obtain actual sign-off outside the Lab. Have consenting peers perform and time the separate usability tasks, recording observed outcomes and feedback, then export sessions. Avoid uploading identifiable or real patient information.

## Readiness check (never a substitute for faculty verification)

Use the `testpilot-lab/facultyReadiness.cjs` command after preparing a **private** evidence manifest. Its JSON shape is:

```json
{
  "experiments": "./testpilot-real-llm-study.json",
  "peers": "./testpilot-peer-usability-observations.json",
  "reviews": {
    "US-001": "./us001-independent-human-reviews.json",
    "US-005": "./us005-independent-human-reviews.json",
    "US-017": "./us017-independent-human-reviews.json"
  }
}
```

Place the real files beside the manifest. Run:

```bash
node testpilot-lab/facultyReadiness.cjs ./evidence-private/evidence-manifest.json
```

The validator refuses to mark complete when ten fully rated genuine-shaped model records, both reviewer sets or two consenting peer sessions are absent; it flags unresolved disagreements. **A structurally valid JSON file cannot independently prove provider provenance or human identity**, so the evaluator must still inspect genuine exports and verify signatures.
