## Executive summary

Test Pilot is a working AI-assisted testing tool for an existing doctor-appointment healthcare application. It converts documented user stories into structured test-case suggestions using Google Gemini, supports human review and editing, compares suggestions with a manual baseline, and runs source-reviewed Playwright checks in an isolated synthetic environment.

The project has **25 documented user stories**, **15 use cases**, and **36 manual test designs**. **Ten real guided Gemini calls** generated **40 suggested designs** across registration, approved-doctor browsing and appointment booking. A preliminary technical comparison against **13 relevant manual cases** found **4 covered, 4 partial and 5 missing**. The most recent verified GitHub Actions run [#42131317272](https://github.com/Akash-annavarapu/doctor-appointment-booking-system/actions/runs/42131317272) completed **29 Playwright PASS, 1 SKIP, 0 FAIL** with successful frontend, backend and case-level evidence export.

The team reports that all six planned activities are complete. The available archived human-study files do not independently authenticate all external reviewer sign-offs or reconcile all usability observations. Those limits are documented rather than changing original records.

## 1. Objective and scope

The purpose is to improve quality-assurance test design for registration, authentication, approved-doctor discovery, appointments and validation across patient, doctor and administrative workflows. The platform suggests **positive, negative, boundary and security** scenarios, while retaining human control before supported execution.

**Workflow:** User story and source acceptance criteria → Gemini output → human review → AI/manual comparison → fixed source-reviewed Playwright assertions → GitHub Actions results and traceable artifacts.

State-changing automated checks use synthetic users and a disposable local MongoDB database. The tool never executes arbitrary LLM JavaScript or mutates live patient records.

## 2. Gemini study and manual comparison

The ten **guided** runs are part of an original 13-run Gemini export; three additional real runs are excluded from the primary comparison.

| Selected story | Guided runs | Candidate designs |
| --- | ---: | ---: |
| US-001 — Patient registration | 3 | 12 |
| US-005 — Browse approved doctors | 3 | 12 |
| US-017 — Appointment booking | 4 | 16 |
| **Total** | **10** | **40** |

**Model recorded:** `gemini-3.5-flash-lite`. The mean model-response duration was **7.61 seconds per guided call** (not measured total human time). Saved operator-entered scores averaged **2.70/5 completeness**, **2.00/5 accuracy** and **4.40/5 healthcare relevance**; these are not authenticated independent-panel ratings.

| Comparison scope | Covered | Partial | Missing | Fully covered |
| --- | ---: | ---: | ---: | ---: |
| 13 relevant manual cases | 4 | 4 | 5 | 30.8% |
| 12 strict core-story cases | 4 | 4 | 4 | 33.3% |

“Covered” means a generated case clearly describes a scenario and observable expected behavior; “partial” means some necessary detail is missing; “missing” means no adequate guided match was found. These are **assistant-assisted case-design classifications**, **not execution pass rates or independently ratified human findings**.

**Observed strengths:** registration success, missing-field rejection, valid booking and concurrent-booking intents.  
**Observed limitations:** wrong registration request field (`mobile` instead of `phone`), invalid example phone numbers, missing exact 7/8-character password boundaries, normalized duplicate-email validation, inadequate pending-doctor filtering and empty-state assertions, and missing out-of-working-hours booking.

## 5. Conclusion and readiness

Test Pilot provides an end-to-end AI-assisted software testing workflow with genuine model responses, a structured human-review mechanism, a curated manual baseline and traceable isolated Playwright execution. The evidence supports successful **technical implementation** and a useful **preliminary design-quality comparison**. It does not demonstrate generalized AI superiority, verified reduction in person-hours, or successful execution of all original generated narratives.

The project and this report are ready for academic review. The team reports its six activities completed, while **formal faculty acceptance** and any separately held human sign-offs/corrected observation records remain outside the material independently verified here.
